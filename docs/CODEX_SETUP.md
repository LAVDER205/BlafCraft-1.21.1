# Работа с Codex

## Проверенные настройки репозитория
- Основная ветка: `main`.
- JDK: 21 (в существующем GitHub Actions используется Temurin).
- Gradle Wrapper: 9.2.1; ModDevGradle: 2.0.140.
- Загрузчик: NeoForge 21.0.167.
- В `gradle.properties` указано Minecraft 1.21.1, а NeoForge и Parchment относятся к линии 1.21. Это отдельный вопрос совместимости; данный PR не меняет версии.

## Локальная работа
Откройте локальную копию репозитория как проект Codex. Проверьте, что установлен JDK 21 и `java -version` показывает нужную версию. Codex получает правила проекта из корневого `AGENTS.md`.

Создавайте отдельную ветку `codex/<задача>` от нужной базовой ветки. Проверка в PowerShell:

```powershell
.\gradlew.bat --no-daemon build
```

В Linux:

```sh
./gradlew --no-daemon build
```

## Облачная среда
Если используете Codex с облачным окружением, выберите этот репозиторий и нужную ветку, обеспечьте наличие JDK 21 и доступ к загрузке Gradle, плагинов и Minecraft/NeoForge-зависимостей. Проверка готовности среды: `java -version`, `./gradlew --version`, затем `./gradlew --no-daemon build`. Не добавляйте токены в репозиторий.

Доступ через GitHub-коннектор проверен в текущем чате; это само по себе не подтверждает настройку отдельного облачного окружения.

## Проверка и слияние
Существующий `.github/workflows/build.yml` запускает сборку на push и pull_request с JDK 21. Дождитесь результата проверки PR и просмотрите изменения перед слиянием. Автоматическое слияние не требуется.

`AGENTS.md` задаёт инструкции агенту, но не заменяет ограничения GitHub. Для технического запрета прямых изменений main владелец может отдельно настроить ruleset: обязательный PR и успешную проверку Build. В этом PR настройки доступа и защиты веток не меняются.

Пример первой задачи: «Проанализируй регистрацию блоков и предметов. Найди возможные ошибки, укажи файлы и предложи минимальное исправление в отдельной ветке. Выполни сборку и подготовь PR; main не изменяй».

Документация: https://learn.chatgpt.com/docs/agent-configuration/agents-md
